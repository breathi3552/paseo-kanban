# Paseo Kanban 0.1.3

## Changes

- Open Kanban as a workspace tab from the `+` menu and place it beside agents or terminals with Paseo's native split controls. The sidebar entry remains available.
- Workspace tabs initially filter to their project's tasks. Filters are independent across open boards; tasks and lanes remain shared on the same host.
- Adapt the toolbar and board to narrow splits using the board's measured width.
- Keep project filtering available by ID when project names cannot be loaded.
- Clean up surface, sidebar, and workspace-panel registrations when the plugin unloads.
- Consolidate drag commits through the existing reorder callback and refresh workspace-panel tests and domain documentation.

## Release integrity

Publishing now runs directly on an existing version tag. The workflow verifies that the tag, package manifest, lockfile, and GitHub Actions source commit agree before publishing with npm provenance. It compares every published file with the tagged source and verifies npm signatures before creating the GitHub Release, which includes the exact npm tarball.

This release replaces `0.1.2` for registry review because that version's provenance identified the commit before its version bump. The registry reported no runtime drift or malicious behavior in `0.1.2`.

## Compatibility and validation

- Requires Paseo `>= 0.8.0`; no board-data migration or dependency changes.
- Development and CI use Node.js 24.
- Automated validation: `npm run check`, published-file comparison, provenance source checks, and `npm audit signatures` in the release workflow.
- Native layout and gestures require the manual host checks in `docs/development.md`; automated tests use host substitutes.

## 变更摘要

- 新增工作区看板标签页，支持与 Agent、Terminal 原生分屏；保留侧边栏入口。
- 工作区默认筛选所属项目，各入口筛选独立，任务和泳道在同一宿主共享。
- 适配窄分屏；项目名称读取失败时仍可按 ID 筛选。
- 完善插件卸载清理，收敛拖拽提交接口，更新测试与领域文档。
- 从已提交的版本 tag 发布，核对 npm 包、来源证明及源码，并将同一 npm tarball 附加到 GitHub Release。
