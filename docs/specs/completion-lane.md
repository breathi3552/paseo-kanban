# 完成泳道与任务完成状态

## 问题与解决方案

现有“已完成”只是普通泳道，无法保留完成任务的普通泳道归属、记录完成时间或稳定恢复任务。增加任务层完成状态与唯一完成泳道：普通归属保持不变，界面根据完成状态选择显示位置。

本规格来自已确认的需求讨论，领域定义见 `CONTEXT.md`，设计取舍见 `docs/adr/0005-completion-lane-and-task-restoration.md`。

## 用户故事与验收规则

1. 作为看板用户，我希望初始化时就有一条完成泳道，以便完成任务有固定显示位置。它始终恰好一条，位于最右端，可以改名，但不可删除或更换完成用途；新普通泳道插入它之前。
2. 作为看板用户，我希望卡片左侧有任务完成 checkbox，以便直接完成或恢复任务。它显示任务层完成状态，与卡片详情轻点、拖拽和子步骤勾选互不干扰。
3. 作为看板用户，我希望完成任务保留普通泳道归属，以便取消完成时返回该泳道。完成时不改 `laneId`，已完成任务只显示在完成泳道。
4. 作为看板用户，我希望取消勾选后任务回到归属泳道末尾，以便继续工作。归属泳道已删除时，使用当前最右侧普通泳道并追加末尾。
5. 作为看板用户，我希望完成任务的归属引用不阻止删除普通泳道，以便清理阶段。包含未完成任务的泳道仍不可删除，且至少保留一条普通泳道。
6. 作为看板用户，我希望拖入完成泳道等同勾选完成，以便沿用拖拽操作。进入完成泳道的落点不决定显示排序，反馈槽位在顶部。
7. 作为看板用户，我希望完成泳道内部无法拖动排序，以便保持按完成时间显示。内部落位不改变任务、时间或持久次序，也不产生保存。
8. 作为看板用户，我希望可以将完成任务拖到任意普通泳道，以便重新开展工作。任务取消完成、更新普通归属，并按可见落点插入；项目筛选下仍保留隐藏任务及其相对顺序。
9. 作为看板用户，我希望最近完成的任务排在前面，以便查看最新成果。使用最近一次未完成到完成的时间；再次完成刷新时间，重复完成、内容编辑、子步骤编辑或详情修改归属均不刷新时间。相同时间稳定保留原数组次序。
10. 作为看板用户，我希望任务完成与子步骤独立，以便保留实际检查进度。子步骤未全完成不阻止任务完成，任务完成或恢复不改变子步骤。
11. 作为看板用户，我希望完成任务仍能编辑详情和普通归属，以便调整计划。详情仅列普通泳道；修改归属后仍完成，随后取消完成返回新归属泳道末尾。
12. 作为看板用户，我希望任务先在普通泳道创建，以便总有业务归属。完成泳道无新建入口，新建和编辑的泳道选择均排除完成泳道，领域层也拒绝直接创建到完成泳道。
13. 作为已有用户，我希望升级时保留原 `done` 泳道名称和任务，以便无损迁移。原 `done` 成为完成泳道，其任务设为完成，普通归属设为最右普通泳道；历史完成时间未知，保留原相对顺序并排在新完成任务之后。
14. 作为已有用户，我希望删除过默认泳道的看板也可升级，以便继续使用。缺少 `done` 时创建完成泳道；缺少普通泳道时补一条“待规划”。迁移不改变其他任务内容、项目、子步骤或普通泳道相对次序。
15. 作为多入口用户，我希望所有入口共享完成状态而筛选保持独立，以便侧边栏和工作区始终一致。项目筛选同时适用于普通泳道和完成泳道，重开后状态与完成排序来自宿主存储。
16. 作为看板用户，我希望保存冲突或失败时原数据保留，以便避免静默覆盖。完成和拖拽操作使用现有整板版本校验；失败显示中英文错误，不更新任务状态或完成时间。保存期间禁止重复操作，拖拽锁期间 checkbox 不发起写入。

## 数据与接口决策

- 设置版本升级为 2，使用 SDK 已支持的 `defineSettings.migrate(values, fromVersion)`。版本 1 数据经独立迁移后进入版本 2 校验；版本 2 数据严格验证，不悄悄重置损坏数据。
- 泳道增加 `isCompletionLane`，普通泳道为 false，唯一完成泳道为 true。角色没有编辑入口；只允许编辑名称。
- 任务增加 `completed` 与 `completedAt`。未完成任务的 `completedAt` 为 null；新完成任务记录非负整数毫秒时间；迁移的历史完成任务允许 null 表示未知时间。
- 未完成任务必须引用存在的普通泳道；完成任务可保留已删除的普通泳道引用，但不能归属于完成泳道。
- `shared/kanban.ts` 提供完成转换和泳道显示任务选择接口，集中处理状态、归属、恢复、时间、排序和筛选。普通泳道继续使用数组手动排序；完成泳道使用时间派生排序。
- `client/kanban-session.ts` 提供带 `baseRevision` 的完成操作，重用现有保存结果与冲突处理约定；详情保存保留完成元数据，包括归属泳道已被删除时仅编辑内容的场景。
- `client/kanban-board.tsx` 负责 checkbox 保存与共享订阅；`kanban-lane.tsx` 使用派生显示集合；`kanban-card.tsx` 将 checkbox 与轻点/拖拽响应区域分开。
- 拖拽控制器识别完成泳道角色，禁止完成泳道内部有效落点；普通任务拖入时显示顶部槽位，拖出仍使用已有普通泳道可见槽位算法。动画取消、卸载或无效落点不提交完成转换。
- 卡片 checkbox 提供 checkbox 语义、checked/disabled 状态与中英文标签。所有失败路径沿用现有显示错误机制。

## 范围之外

不增加多条完成泳道、归档、任务完成历史日志、自动完成子步骤、跨宿主同步或自动合并冲突；不改变现有项目筛选及普通泳道排序语义，不发布 npm 版本。Paseo 真实宿主 UI 与原生手势验收仍按 `docs/development.md` 执行，云环境未提供 Paseo CLI。

## 交付流程

新分支承载规格、领域文档、初始测试与实现；全部初始测试见到预期失败后开始实现。完整检查通过后执行 code-review 的标准轴与规格轴独立审查；发现的问题只修改业务代码或文档，不新增测试点。最终提交经过审查的分支成果。
