# 保留普通泳道归属的完成视图与任务恢复

## 状态

已接受。需求提出者已确认完整共识，实现遵循 [完成泳道规格](../specs/completion-lane.md)。

## 背景

当前泳道只有身份与标题，任务阶段由所属泳道表达；默认 `done` 泳道并无特殊用途约束。任务的持久次序由整板任务数组表达，普通泳道支持拖动排序，见 [ADR-0001](./0001-task-ordering-and-drag-animation.md) 与 [ADR-0002](./0002-task-reordering-and-drag-lifecycle-convergence.md)。整板数据由宿主存储，通过版本校验保存，见 [ADR-0004](./0004-host-board-storage-and-project-references.md)。

新增需求要求完成任务集中展示，并能在取消完成时返回原普通泳道。需求讨论确定：完成状态决定任务的显示位置，完成泳道不成为任务的业务归属。

## 已确定的决策

- 同一看板始终恰好一条完成泳道，首次初始化即创建；不可删除或更换身份，可以改名，固定排列在最右端。
- 完成泳道自身仍保存在泳道列表中，保存身份、名称和完成用途属性；它是任务的显示视图，不是任务的普通泳道归属。
- 任务持久数据保留普通泳道归属，完成时不更改 `laneId`；是否完成决定其在普通泳道或完成泳道显示，不另存一份完成前泳道记录。
- 点击完成与拖入完成泳道产生相同效果：设置任务完成状态，保留普通泳道归属，在完成泳道显示。
- 点击取消完成后，任务显示在当前 `laneId` 所指的普通泳道末尾；如果归属泳道已删除，改为归属于当前最右侧普通泳道，即完成泳道左侧相邻泳道，并显示在其末尾。
- 可以将完成任务拖出至普通泳道；这会取消完成并将 `laneId` 改为实际拖入的普通泳道，按实际落点插入。
- 完成泳道内部不允许拖动排序，任务仅按完成时间由近到远显示。
- 已完成任务保留的普通泳道归属不阻止删除该泳道；同一看板至少保留一条普通泳道。
- 完成泳道不允许直接创建任务；任务完成与子步骤完成相互独立。
- 卡片内左侧新增任务完成 checkbox；勾选完成，取消勾选则取消完成。它与子步骤完成状态独立。
- 任务详情中的泳道选择仅列普通泳道；已完成任务在详情中改选普通泳道时，只修改 `laneId`，保持已完成与完成时间不变。之后取消勾选时返回新选择的普通泳道末尾。
- 每次任务从未完成变成完成时记录新的完成时间；取消后再次完成会更新该时间，重新按最近完成排序。编辑内容、子步骤或重复完成操作不刷新完成时间。
- 升级既有看板时，将原 `done` 泳道设为完成泳道并保留其名称；其中已有任务视为完成，普通泳道归属设为最右侧普通泳道。缺少原 `done` 时新建完成泳道。
- 旧 `done` 任务的真实完成时间不可知：保留其原相对顺序，显示在之后新完成的任务后面，不将升级时间伪作真实完成时间。

## 后果与取舍

- 完成泳道形成普通泳道手动排序规则的例外；拖入时的位置不能决定完成任务的显示顺序。
- 保留 `laneId` 即可表达恢复目标，避免在完成时迁移归属并另存历史泳道；显示逻辑需要区分业务归属与完成视图。
- 已完成任务允许保留失效的普通泳道引用；当前模型要求所有任务引用有效泳道，后续实现需要调整这一约束，并保证未完成任务始终有有效的普通泳道归属。
- 泳道删除时需要区分未完成任务与保留该泳道归属的完成任务，不能继续用全量任务引用判断是否可删除。
- 现有看板数据尚不具备任务层完成状态与完成时间；已有 `done` 任务的升级使用已确认的归属回退与历史排序规则，无法还原其历史完成前泳道与完成时间。
- 完成泳道的任务显示顺序由完成时间决定，普通泳道继续使用已有手动排序规则；任务归属、完成状态与显示位置必须分别处理。

## 实现与兼容

设置版本从 1 升级为 2，通过宿主支持的迁移合同转换旧看板。`shared/kanban.ts` 集中实现完成状态转换、泳道显示集合与旧数据迁移；`client/kanban-session.ts` 负责版本校验保存；卡片 checkbox 与拖拽区域分开，完成泳道作为显示来源传入拖拽控制器。

普通泳道仍使用任务数组次序，完成泳道按完成时间派生显示次序；这构成 ADR-0001 与 ADR-0002 普通排序规则的明确例外。详情修改普通归属不取消完成，拖出完成泳道则取消完成并按落点插入。
