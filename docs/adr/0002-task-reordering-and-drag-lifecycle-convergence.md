# 筛选排序语义与版本冲突处理

项目筛选仅决定哪些任务可见，不改变持久化任务集合。`shared/kanban.ts` 的 `reorderTask` 根据可见槽位寻找目标泳道的相邻可见任务，将移动的任务插入全量数组的该锚点前后，保持隐藏任务的相对次序。持久化沿用宿主的 `save(board, revision)` 版本校验；发生冲突时报告失败，不自动合并或重放拖拽。

## 边界规则

- 跨泳道移动且目标泳道只有隐藏任务时，将任务追加到该泳道已有任务之后；目标泳道完全为空时按泳道次序寻找邻近任务确定数组位置。
- 同泳道筛选下仅被拖任务可见时，唯一槽位代表原位，返回原看板并跳过写入。其他排序若得到相同数组次序也跳过写入；`client/kanban-session.ts` 用返回对象是否同一引用判断 `unchanged`。
- `client/kanban-drag.ts` 在释放时固定目标泳道、可见插入索引和 `operationId`；动画完成后由 `client/kanban-board.tsx` 的排序回调读取**当时**的看板、版本号和筛选条件，传给 `executeTaskReorder`。拖拽锁阻止界面切换筛选和打开编辑会话。数据基准取自落位提交时；外部推送若在拖拽期间更新看板，释放时的可见索引可能对应新的数据。这一风险留给后续代码任务验证和处理。
- `save` 返回 `false` 或抛出异常时，排序报告失败，保留宿主当前看板并释放拖拽锁。任务/泳道编辑会话在打开时捕获 `baseBoard` 与 `baseRevision`，各自维护草稿；保存失败保留草稿，由用户核对最新数据后重试。

该策略是**乐观并发控制**：依赖宿主校验 `revision`，不作静默覆盖。落位动画与写入之间的边界见 [ADR-0001](./0001-task-ordering-and-drag-animation.md)。
