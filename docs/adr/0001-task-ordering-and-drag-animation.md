# 任务次序与拖拽落位

任务的持久次序由 `board.tasks` 数组表达，不另设 `rank` 字段。拖拽控制器按可见卡片计算落点，领域函数将可见槽位映射回全量数组；动画负责反馈，只有有效落位完成后才提交排序。这样既能在项目筛选下排序，也能维持隐藏任务的相对次序；另设排序字段会增加同步与迁移成本。详见 [ADR-0002](./0002-task-reordering-and-drag-lifecycle-convergence.md) 的边界规则。

## 当前实现与回归边界

- `client/kanban-drag.ts`：全卡片主体可轻点编辑或抓起；鼠标移动达到 5px 激活拖拽，触屏长按 220ms 激活拖拽，触屏长按前移动达到 5px 则让渡给滚动；左侧手柄立即抓起。激活后互斥锁隔离轻点操作。
- 命中先将指针的视口坐标换算为随横向滚动变化的内容坐标，再计算泳道及可见插入槽位。相邻卡片边界使用 8px 迟滞区避免占位槽抖动；左右边缘 48px 区域驱动自动横向滚动。占位槽采用 React Native `Animated` 与布局避让，无需额外原生动效库。
- `client/kanban-overlay.tsx`：有效目标释放后，悬浮卡片吸附到目标占位槽；动画完成调用 `commitDrop`。动画中断调用 `abortDrop`。在看板外释放则回弹，不提交排序。
- 控制器的 `operationId` 使落位回调只提交一次；卡片或看板卸载清理待执行手势、动画状态与监听，`lifecycleEpoch` 隔离迟到的保存结果。保存或取消后释放互斥锁，下一次交互不受阻塞。

上述毫秒数和像素数是**当前实现参数**；稳定约束是轻点/拖拽/滚动分流、可见槽位命中、动画与提交顺序、幂等和取消/卸载清理。调整参数时同步检查相关测试和宿主手势验收。
