# 任务次序与拖拽落位

普通泳道中未完成任务的持久次序由 `board.tasks` 数组表达，不另设 `rank` 字段。拖拽控制器按可见卡片计算落点，领域函数将可见槽位映射回全量数组；动画负责反馈，只有有效落位完成后才提交排序。这样既能在项目筛选下排序，也能维持隐藏任务的相对次序；另设排序字段会增加同步与迁移成本。详见 [ADR-0002](./0002-task-reordering-and-drag-lifecycle-convergence.md) 的边界规则。完成泳道按完成时间派生排序，禁止内部拖动排序，见 [ADR-0005](./0005-completion-lane-and-task-restoration.md)。

## 当前实现与回归边界

- `client/kanban-drag.ts`：依照 [#25](https://github.com/breathi3552/paseo-kanban/issues/25)，卡片不再显示拖拽把手；除完成 checkbox 与发送按钮外的全区域均可抓起或右键打开菜单，桌面左键单击不再编辑详情。鼠标移动达到 5px 激活拖拽；触屏保留轻点详情、长按 220ms 激活拖拽，长按前移动达到 5px 则让渡给滚动。激活后互斥锁隔离其他卡片操作。
- 命中先将指针的视口坐标换算为随横向滚动变化的内容坐标，再计算泳道及可见插入槽位。相邻卡片边界使用 8px 迟滞区避免占位槽抖动；左右边缘 48px 区域驱动自动横向滚动。占位槽采用 React Native `Animated` 与布局避让，无需额外原生动效库。
- `client/kanban-drag.ts` 对界面仅提供容器、泳道/卡片、悬浮卡片绑定与必要锁状态；完整控制器保留为内部实现和几何行为测试入口。悬浮卡片专用绑定独立订阅高频指针更新，看板只订阅槽位和落位变化。
- `client/kanban-overlay.tsx` 仅呈现悬浮卡片；`useKanbanDragOverlay` 在拖拽模块内完成吸附动画、操作标识核对与提交协作。有效目标释放后先吸附到目标占位槽，仅动画完成后提交；动画中断、取消或卸载不提交，旧动画回调不能提交新操作。在看板外释放则回弹，不提交排序，不设超时自动提交。
- 控制器的 `operationId` 使落位回调只提交一次；卡片或看板卸载清理待执行手势、动画状态与监听，`lifecycleEpoch` 隔离迟到的保存结果。保存或取消后释放互斥锁，下一次交互不受阻塞。

上述毫秒数和像素数是**当前实现参数**；稳定约束是轻点/拖拽/滚动分流、可见槽位命中、动画与提交顺序、幂等和取消/卸载清理。调整参数时同步检查相关测试和宿主手势验收。
