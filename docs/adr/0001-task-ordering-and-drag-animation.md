# 任务次序模型与拖拽提交生命周期

## 状态

已接受（合并并取代原 ADR-0002）。

## 背景

看板需要支持同泳道拖拽重排与跨泳道移动。在多项目共享看板、项目筛选视图以及并发多端编辑场景下，任务排序需要兼顾以下约束：

1. 项目筛选仅改变可见集合，不能破坏未显示任务的既有相对顺序；
2. 完成任务与未完成任务并存，完成泳道有独立的按完成时间派生排序规则（见 [ADR-0005](./0005-completion-lane-and-task-restoration.md)）；
3. 拖拽交互必须具备确定性的提交流程与并发保护，防止网络或渲染抖动导致数据错乱。

## 决策

### 1. 数组隐式次序表达，不设 `rank` 字段

普通泳道中未完成任务的持久次序纯粹由 `board.tasks` 数组的元素顺序表达，不在任务对象中另设 `rank` 浮点数或整型权重字段。

- **原因**：在项目筛选、跨项目共存及批量导入场景下，浮点 rank 需要维护复杂的精度重平衡（rebalance）和跨项目同步；直接使用全量数组索引表达顺序，开销最低且状态唯一。

### 2. 筛选态下的“可见槽位锚点映射”

在项目筛选激活时，拖拽落点仅对应当前可见卡片的相对槽位：

- 排序函数通过可见槽位定位目标普通泳道中相邻的前后可见未完成任务作为“锚点”；
- 将被移动的任务插入全量数组中该锚点的前后，原泳道和目标泳道中处于隐藏状态的任务保持相对顺序不变；
- 归属于该泳道但已完成的任务不作为排序锚点；
- 跨泳道移动至只有隐藏任务的泳道时，追加至该泳道任务末尾；目标泳道为空时按泳道顺序就近插入。

### 3. 拖拽落位与提交生命周期

- **动画优先与延迟提交**：指针释放后先执行占位吸附动画，只有有效落位动画完全结束后才提交排序；动画中断、手势取消、组件卸载或看板视口外释放均直接终止并回弹，不触发写入。
- **单次幂等与代次隔离**：拖拽控制器分配唯一的 `operationId` 保证一次拖拽仅触发一次有效落位；生命周期代次（lifecycle epoch）隔离迟到的异步回调，避免前次操作的结果污染后续交互。
- **无变更跳过**：若排序计算后的全量任务数组与原数组引用完全一致，直接跳过持久化写入。

### 4. 乐观并发冲突策略

- 排序持久化沿用宿主设置的 `save(board, revision)` 乐观锁校验。
- 发生版本冲突（revision 不匹配）或写入异常时，直接报告失败并释放拖拽锁定，不进行自动合并，也不自动重放拖拽操作，由用户基于最新看板状态重新发起交互。

## 边界与例外

- 完成泳道由完成时间派生排序，禁止内部拖拽重排；拖入完成泳道仅转换完成状态并保留普通归属；拖出完成泳道取消完成、更新归属并按落点插入全量数组（详见 [ADR-0005](./0005-completion-lane-and-task-restoration.md)）。
- 泳道结构本身的排序采用“本地预览、显式保存”状态机，与任务拖拽的“释放即落位提交”相互独立（详见 [ADR-0007](./0007-unified-lane-management-and-portal-rendering.md)）。
