# 项目仓库的 GitHub Issue 单向导入

## 状态

已实施。需求提出者于 2026-10-16 在 [Issue #15](https://github.com/breathi3552/paseo-kanban/issues/15) 的设计讨论中确认了功能边界及 UI/UX 约定。代码实现已在 PR #22 中合并落地，SDK 已升级至 `@getpaseo/plugin@0.11.4`，并通过自动化测试与代码审查（见 [Issue #15 实现验证](../verification/issue-15.md)）；真实宿主交互验收按 [开发指南](../development.md#5-github-issue-导入验收) 执行。

## 背景

Issue #15 希望将项目对应 GitHub 仓库中的 Issues 导入看板，减少重复录入。初始提案同时提出一次性导入和持续同步两种方向，需要明确数据归属及来源范围。

现有看板在同一宿主内共享，任务可关联 Paseo 项目，项目筛选仅改变可见集合，见 [ADR-0004](./0004-host-board-storage-and-project-references.md)。任务完成状态与普通泳道归属已有独立规则，见 [ADR-0005](./0005-completion-lane-and-task-restoration.md)。

## 已确定的决策

- Issue 导入是一次性的单向复制。导入后的任务由看板独立管理，后续 Issue 变化与任务无关。
- 不持续拉取或用 Issue 后续内容更新已导入任务；任务编辑、完成或删除也不回写 GitHub。
- 每个 Paseo 项目的导入来源与该项目代码目录对应的 GitHub 仓库一一对应，不提供从其他仓库导入的能力。
- 首版支持 GitHub.com 的公开与私有仓库。
- 只读取 Open Issues，由用户勾选后导入；已导入的 Issue 置灰且不可勾选。
- 去重按当前看板中任务的项目 ID 与 Issue 编号共同判定，不使用链接作为去重键。完成任务仍参与判定，任务删除后允许再次导入，不维护永久导入历史。
- 任务新增任务来源、Issue 编号、外部链接三个字段。GitHub 导入任务的来源为 GitHub Issue，外部链接为该 Issue 的网址；旧任务统一归为手动创建，Issue 编号和外部链接为空。
- 任务来源与 Issue 编号属于内部属性，不展示为任务详情字段或卡片标签；来源用于控制外链按钮显示，Issue 编号用于导入去重。
- Issue 标题复制为任务标题，正文复制为任务描述，子步骤初始为空。
- 列表副文本不出现在任务卡片；导入时在任务正文后追加分隔线，再以普通文本摘入 Issue 编号、作者及绝对创建时间。摘录使用导入时语言，存入后不随语言切换重新生成。仅新增已明确的三个任务属性，不新增作者、Issue 创建时间等任务字段。
- GitHub 导入任务的关联项目固定为导入时选择的 Paseo 项目，任务详情不允许更改。
- 固定使用项目代码目录的 Git remote `origin`，复用 Paseo daemon 所在机器的 `gh` 登录态读取仓库 Issues。

## 已确认的交互要求

- 看板右上角的“添加任务”按钮替换为“从 GitHub 导入”，点击打开导入弹窗。
- 弹窗通过下拉框选择项目，再读取其对应仓库的 Open Issues，使用两列表格展示。
- 弹窗增加目标泳道下拉框，用户选择导入到哪条普通泳道。
- 表格第一列为复选框，第二列主文本为 Issue 标题，下方展示编号、作者及相对创建时间，随当前界面语言呈现。
- 中间列表可滚动；使用类似 GitHub 的分页，每页 25 条，单次导入上限为 25 项，翻页清空此前勾选，不采用“加载更多”。
- 默认从新到旧排序，在表头 Issue 单元格内提供切换按钮，支持由旧到新和由新到旧。
- 已导入行仅置灰并禁用复选框，不额外显示“已导入”文字。
- 底部左侧显示选择计数，提交按钮文案固定为“导入”，不在按钮内重复计数。
- 卡片仅增加外部链接图标，不新增来源或编号展示；手动创建任务不显示该图标。
- 点击外链图标使用系统浏览器打开来源 Issue。
- GitHub 导入任务的详情在项目与描述之间展示高亮的文本超链接，文本使用完整的 Issue 网址。
- 已接受卡片外链图标位于标题行最右侧、点击仅打开网页；详情项目呈只读项目名，完整链接过长时换行。
- 新功能遵循项目现有中英文 i18n 和语言切换规则，见 [ADR-0003](./0003-internationalization-and-locale-adaptation.md)。
- 项目默认沿用当前有效项目筛选，否则等待用户选择；目标泳道默认第一条普通泳道。
- 分页控件位于表格下方；桌面提供上一页、页码和下一页，窄屏提供上一页、当前页和下一页。全选仅作用于当前页可导入项。
- 按 Issue 创建时间在整个来源仓库的 Open Issues 中排序。切换排序或项目返回第 1 页并清空勾选；切换目标泳道保留页码、排序及勾选。
- 新任务初始未完成，按列表次序追加至目标泳道末尾；导入成功关闭弹窗、提示数量，当前筛选会隐藏新任务时切换至导入项目。
- 读取、空列表及错误状态在列表区域呈现；保存失败保留弹窗及仍有效的勾选，不静默覆盖或自动重复提交。

## 后果与取舍

- 用户在看板中编辑导入任务时，无需处理 GitHub 后续修改带来的覆盖或合并冲突。
- 本功能无需建立任务状态与 Issue 状态的持续映射，也不承担关闭、重新打开或删除 GitHub Issue 的职责。
- GitHub 上后续的更正不会自动反映到既有任务；这是一次性导入的明确行为。
- 导入前通过项目代码目录的 `origin` 确定来源，不自动改用 `upstream`；缺少或不支持该 remote 时展示具体原因。
- 私有仓库访问权限来自 daemon 所在机器的 `gh` 登录态；客户端本机登录不能代替该授权。
- 保存任务来源与 Issue 信息需要兼容旧数据；旧任务的默认来源为手动创建，不推断既有描述中的链接或编号。
- 项目关联锁定是导入任务的领域约束，不能只靠详情页禁用选择器表达。
- 项目 ID 与 Issue 编号是已确认的去重依据。若同一项目日后更换 `origin` 仓库，编号相同的已有任务仍会阻止导入；本次没有将其扩展为仓库维度的去重。
