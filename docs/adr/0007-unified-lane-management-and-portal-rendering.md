# 统一泳道管理、Portal 渲染与并发安全保存

## 状态

已接受。实现遵循 [泳道管理规格 (#24)](https://github.com/breathi3552/paseo-kanban/issues/24)。

## 背景

原有看板的泳道操作分散在各泳道头部，仅支持单一泳道的新增与编辑，不支持横向重排；当泳道内包含任何任务时，删除操作直接报错拒绝。宿主 SDK 0.11.4 提供的标准 Modal 在桌面端固定宽度为 520px，无法容纳看板全部泳道的横向平铺展示。同时，看板采用整板单版本存储（[ADR-0004](./0004-host-board-storage-and-project-references.md)），在多工作区或多端并发场景下，其他会话的任务变动会导致泳道编辑因 revision 不匹配而保存失败。

为解决上述问题，系统引入集中式泳道管理弹窗，支持横向重排与级联删除，并通过自定义 Web Portal 与细粒度 CAS 保证交互与并发安全。

## 已确定的决策

### 1. 统一管理入口与横向布局

- 移除各普通泳道头部的“管理”按钮，在看板顶栏提供全局单一的“管理泳道”入口，集中管理所有泳道。
- 弹窗采用横向滚动卡片视图，直接映射主看板的横向排列直觉；完成泳道固定位于最右端，不可向前排列，不可删除。
- 泳道名称去除首尾空格后在整板范围内唯一，完成泳道同样参与判重；校验失败在表单内行内提示，不触发 Toast 通知。

### 2. 宽屏 Web Portal 与层级隔离

- 桌面端（Web 平台且非 compact 视图）使用独立打包的 React DOM 19.1.0 `createPortal` 产物（`client/web.ts`），将弹窗直接挂载至 `document.body`，突破宿主 520px 宽度限制，提供最大 1120px 视口；窄屏与移动端回退至宿主原生 Modal。
- Portal 容器层级固定为 `z=0`，位于普通应用内容之上，但在宿主 overlay plane（`z=1`）之下。该设计保证宿主全局 Toast 和命令面板正常覆盖在管理弹窗之上，不遮挡操作反馈。
- 实现完整的桌面键盘与焦点生命周期：Esc 键关闭、Tab 键焦点圈定（Focus Trap）、以及弹窗卸载后的焦点恢复。

### 3. 泳道重排的“本地预览”状态机

- 普通泳道支持左右移动按钮与把手手势拖拽两种重排方式；拖拽接近视口边缘时触发自动横向滚动。
- 区别于任务卡片拖拽的“释放即落位保存”（[ADR-0001](./0001-task-ordering-and-drag-animation.md)），泳道重排采用“本地预览、显式保存”模式。拖拽与移动仅更新本地预览顺序，点击“保存顺序”提交持久化，点击“还原顺序”放弃变动。
- 存在未保存的排序草稿时，界面拦截新增、重命名与删除操作，防止顺序草稿与结构变动交叉产生状态歧义。

### 4. 级联删除未完成任务

- 允许删除包含未完成任务的普通泳道。当泳道内存在未完成任务时，弹出二次确认对话框说明影响范围。
- 确认删除后，原子化清理全板所有项目中归属于该泳道的未完成任务；已完成任务（`task.completed === true`）继续保留在数据集中，其恢复目标回退至最右侧普通泳道（遵循 [ADR-0005](./0005-completion-lane-and-task-restoration.md)）。
- 最后一条普通泳道及完成泳道继续受到保护，禁止删除。

### 5. 细粒度 CAS 并发安全重试

- 泳道增删改保存遇到宿主 revision 冲突时，系统重新拉取最新看板数据并对比变动差异：
  - **仅任务更新**：若最新数据与基准数据的泳道列表（`lanes`）一致，仅任务列表（`tasks`）发生变化，自动应用最新 revision 重试提交，不打断用户操作；
  - **泳道结构更新**：若外部修改了泳道列表（成员、名称或顺序发生变动），停止自动合并，保留用户当前草稿，并提供“放弃修改并加载最新”的恢复入口。

### 6. 异步生命周期与多语言反馈

- 保存期间卸载管理弹窗或看板，后台异步写入流程继续执行，并在写入终态后触发一次宿主 Toast 通知。
- 异步保存期间若用户切换界面语言，最终成功或失败通知采用切换后的最新语言。

## 后果与取舍

- 自定义 Web Portal 绕过了宿主提供的 Modal 封装，需要自行维护背景蒙层、焦点捕获、无障碍属性及键盘事件；作为权衡，该实现严格基于公开标准 DOM API，不读取或修改宿主私有 DOM 节点。
- 泳道排序需要用户显式点击保存，增加了单次操作的交互步骤，但避免了拖拽过程中频繁触发整板设置写入以及由此引发的高频 CAS 冲突。
- 级联删除未完成任务会跨项目清理任务，属于不可逆破坏性操作，因此引入了强制的二次确认步骤。

## 实现与兼容

- 状态转换函数集中在 `shared/kanban.ts`（`reorderLanes`、`deleteLane`、`requireLaneTitle` 及 `LaneTitleError`）。
- 交互与生命周期由 `client/lane-management-modal.tsx`、`client/lane-management-dialog.tsx` 与 `client/use-lane-reorder.ts` 承载。
- Portal 打包构建由 `scripts/build-portal.mjs` 支持，通过 `npm run check:portal` 作为本地与 CI 质量护栏。
- 看板存储 schema 保持不变（版本 3），无需数据迁移。
