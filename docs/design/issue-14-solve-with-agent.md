# Issue #14：任务内容单向发送到新 Agent

## 状态

2026-10-20 已按需求提出者的 `to-spec` 指令整理规格并发布至 [Issue #14 规格评论](https://github.com/breathi3552/paseo-kanban/issues/14#issuecomment-6283668277)。以下“已确认”条目为实施范围；末节两项默认值保持开放，不把建议写成已接受的决策。功能已实现；本轮根据需求反馈调整卡片操作布局、宿主命名、工作区名称展示及输入框聚焦边框。

需求来源：[Issue #14](https://github.com/breathi3552/paseo-kanban/issues/14)。代码基线为 `65e5700`。

## 已确认的流程与边界

1. 仅在任务卡片上增加传递图标，任务详情不增加入口。卡片最右侧分两排放置小图标：发送对齐标题首行且高度相同，来源对齐下方项目标签且高度相同。用户点击图标后，先选择 Paseo 工作区。
2. 可以选择已有工作区，也可以新建工作区。
3. 将任务内容组织成一套提示词，直接作为初始消息发送并启动新 Agent，随后打开其聊天窗口。
4. 用户已在后续讨论明确选择“直接发送并启动”，取代原先输入框预填的方案；点击卡片入口后，发送弹窗只提供一个 Agent 配置下拉框，从 Paseo 已配置的 Provider、模型、thinking 等整套配置中选择，不分别提供参数控件。默认选中宿主预设列表的第一项，沿用宿主排列顺序，不另存上次选择偏好。
5. 首版采用单向传递，不建立 Agent 运行状态向看板的回流。
6. 每次传递始终新建 Agent 会话，不选择或复用已有会话。
7. 默认展示任务所属项目的工作区；手动创建的任务允许用户主动切换其他项目，未关联项目时先选择项目。主动选择项目时，任务本身的所属项目也更新为所选项目。项目变更在点击最终“传递”时保存，选择过程中不立即保存；取消选择不提交项目变更。GitHub 导入任务不允许改绑项目，仅选择原所属项目下的工作区。
8. 工作区只用一个下拉框，包含所选项目的已有工作区、“新建普通工作区”和“新建 worktree”，不再分开提供已有／新建切换和类型选择器。
9. 提示词保留任务标题、描述、子步骤及来源链接的原文；描述、子步骤或来源为空时，整个对应章节省略。
10. 用户已放弃设置跳转按钮，改为在发送弹窗的预设选择区域保留一条静态小提示。提示说明预设可在 Paseo 设置中管理，不提供链接或跳转操作；设置导航接口不再是实现依赖。
11. 用户已确认没有预设时禁止输入：发送弹窗的表单输入与发送不可用，保留提示与关闭入口。
12. 新建普通工作区和新建 worktree 都自动使用任务标题作为工作区名称，页面不展示新建名称或输入框。已有工作区只在工作区下拉框显示名称，不额外展示名称字段，也不在此重命名。
13. 新建 worktree 时显示独立的“Git 分支名称”输入框，与自动生成的工作区名称独立；用户已确认分支名未填或不合法时就地提示并阻止发送。
14. 工作区下拉框默认选择“新建普通工作区”；新建普通工作区使用项目原目录。
15. 新建 worktree 沿用 Paseo 解析的仓库默认分支作为起点，不增加起点字段。
16. 非 Git 的普通目录项目仅提供已有工作区与新建普通工作区，不提供新建 worktree。
17. 提交所需的项目、工作区选择／新建字段及 Agent 配置必须齐全，未填或不合法时在对应字段提示并阻止发送；新建工作区名称由程序传入，不属于用户必填项。
18. 有项目归属变更时先保存，再按需创建工作区，最后新建并启动 Agent；任一步返回失败则停止本次流程，显示宿主错误 Toast 并保留弹窗输入。此前已成功的操作不自动回滚、不自动重试。

单向交付边界见 [ADR-0008](../adr/0008-one-way-task-dispatch-to-agent.md)。

## 已核实的技术事实

- `@getpaseo/plugin@0.11.4` 使用 `usePaseo()` 访问 SDK；`@getpaseo/client/dist/index.d.ts` 提供工作区列举、新建、Agent 列举及创建接口。
- 该版本的 `navigation.openAgent()` / `openWorkspace()` 支持打开目标，但参数只有目标 ID 与可选宿主 ID，没有输入框预填参数。
- 已检查该版本客户端公开导出、导航合同、按钮与命令合同，以及 [官方插件参考](https://paseo.sh/docs/plugins/reference)；尚未发现从看板写入宿主 Agent 输入框草稿的公开接口。
- 工作区句柄的 `agents.create({ config, title, prompt })` 已能在指定工作区新建 Agent 并提交初始消息；`config.provider` 需要 `providerId/modelId` 组合。
- 已核对 npm 在调研时的最新发布版 `0.12.0` 及 Paseo `main`（`ab6cdb7c896f6e79aaae1ce68b59ca44b1a9c19c`）：宿主内部已有新会话草稿及工作区创建界面，但插件公开导航仍缺少对应接入点。当前已选择直接发送，输入框预填不再是实现依赖，插件内创建表单已按本记录确认。证据见 [宿主接入调研](../research/issue-14-agent-draft-integration.md)。
- 模型目录、默认标记、运行模式、思考选项及动态功能均有公开数据接口；宿主的组合模型选择器和客户端上次使用偏好未作为插件接口导出，详见 [模型选择调研](../research/issue-14-model-selection.md)。
- 当前预设方案可通过 `paseo.config.get()` 读取 `config.agentProfiles`，直接复用宿主配置。内置预设管理位于对应宿主的 Agents 设置页；插件 `openSettings()` 被限制为本插件注册的设置页，不能据此跳转内置页面。
- 自动工作区命名可通过 `workspaces.create({ title: task.title, source: ... })` 实现，普通目录和 worktree 均支持。宿主优先使用显式 `title` 展示名称；`source.branchName` 独立传入，因此中文或空格的工作区名不需要变成 Git 分支名。
- 以上为源码与类型合同核实，尚未完成真实宿主派发验收。

## 后续增补：发送反馈与 prompt

已确认并实现：

- 点击发送后显示 spinner 与“发送中…”，直至跳转或失败，沿用发送期间的表单禁用及防重复提交。
- 弹窗上部新增多行输入框，字段名称在中英文中均为小写 `prompt`，默认预填原开场句。用户只编辑如何开展协作的要求，不编辑完整提示词模板；任务标题、描述、子步骤与来源仍自动附加。
- 点击发送且输入校验通过后，先持久保存指令，再继续原有派发步骤。该指令跨任务沿用；后续创建失败不撤销保存，取消弹窗不保存修改。
- 不改变创建并启动 Agent 的流程；“先讨论需求”是用户可输入的指令示例，不是新增发送模式。

- `prompt` 允许清空；清空后只发送当前任务内容，不恢复默认指令，也不输出多余的开场空行。
- `prompt` 保存失败时停止发送，显示宿主错误 Toast 并保留输入供重试，不继续创建工作区或 Agent。
- `prompt` 是同一宿主内跨任务、跨项目及看板入口共享的持久配置，不包含具体任务内容；自定义文本不随界面语言改写。
- 实施采用 TDD，沿真实发送入口验证行为。编码完成后不再新增测试，并执行独立的代码规范和需求符合度审查；本轮不自动合入。
- 持久化复用宿主设置接口，使用独立的 `agent-dispatch` 设置文档，与看板数据的版本校验隔离；未保存时用当前语言的默认指令，已保存的空字符串不恢复默认值。prompt 是复用偏好，以本次点击发送时的输入文本为最新保存值，使用提交时的当前设置版本；不绑定编辑起始版本，不因其他窗口先保存过而阻止提交。此规则仅适用于 prompt，不改变任务与泳道的版本保护。用户实际修改并保存后按编码约定通知一次。

## 提示词模板

原有结构如下；开场句现替换为已保存或本次编辑的 prompt，具体任务内容结构保持不变：

```markdown
请处理以下任务。

# {任务标题}

## 描述

{任务描述原文}

## 子步骤

- [ ] {未完成子步骤标题}
- [x] {已完成子步骤标题}

## 来源

{来源 Issue 完整链接}
```

- 默认发送指令与章节名采用当前界面语言；英文对应为 `Please work on the following task.`、`Description`、`Steps`、`Source`。用户编辑的发送指令、任务原文及链接不翻译。
- 标题必填，始终输出；模板中的花括号仅为占位说明，不写入最终草稿。
- 描述为纯空白时省略“描述”章节；非空描述保留其原有 Markdown，不自动总结或改写。
- 子步骤数组为空时省略“子步骤”章节；非空时按原顺序逐项输出，保留每项完成勾选状态。
- 来源使用任务已有的 `externalUrl`；为空或纯空白时省略“来源”章节，不输出“无来源”或“手动创建”等占位文字。
- 仅在实际输出的内容块之间保留一个空行，不留下空章节。任务只有标题时，最终消息仅为 prompt 与任务标题；prompt 为空白时省略这一块。
- 不额外添加提交、PR、自动勾选或自动验收等指令。

## Agent 配置提示文案

预设下拉框旁或下方以弱化样式显示简短提示：

- 中文：`前往 Paseo 设置中的 Agent 页面管理 Agent 配置。`
- 英文：`Manage Agent profiles on the Agent page in Paseo settings.`

提示属于静态说明，随界面语言切换。用户已确认无预设时禁止输入及发送；此确认不包含读取失败等其他场景。

## GitHub 导入任务的项目约束

[ADR-0006](../adr/0006-one-way-github-issue-import.md) 规定 GitHub 导入任务固定关联导入项目；`shared/kanban.ts` 的 `updateTask()` 和 `client/kanban-session.ts` 的项目设置逻辑均实施了此约束。需求提出者已明确不允许导入任务改绑项目，因此传递流程继续遵循此规则，仅展示原所属项目的工作区，不提供切换项目的操作。

保留现有 `projectId + issueNumber` 导入去重及来源链接规则，不新增来源项目身份或改绑迁移逻辑。

## 编码约束：异常处理须逐项确认

需求提出者明确要求：

> 禁止私自添加额外异常场景处理。编码时仅实现我已明确确认的异常场景，如果你认为有必要进行防御的异常场景，请向我询问并说明处理异常场景的必要性。

- 已明确确认的处理：没有预设时禁止表单输入及发送；必填项未填或分支名不合法时就地提示并阻止发送；分阶段调用失败时停止本次流程、显示错误 Toast 并保留输入，不自动回滚、不自动重试。
- 提交顺序已明确为项目变更保存、按需创建工作区、新建并启动 Agent。前一步已成功的结果可以保留，后一步失败不触发自动补偿。
- 未获明确确认前，不将其他防御、恢复或重试行为加入本功能实现或验收要求。
- 如认为某项额外异常处理确有必要，先说明具体场景、需要处理的原因及拟采用的行为，向需求提出者询问，得到明确确认后再实现。
