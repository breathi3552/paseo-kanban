# Issue #14：发送到 Agent 弹窗设计

## 状态与范围

2026-10-20，依据需求提出者“详细设计一下页面 /wait-what”的请求编写并随讨论更新。用户现已确认新建工作区自动使用任务标题命名且不在页面体现名称；已有工作区仅在下拉框显示名称，不再重复展示只读名称字段。下文区分已确认交互与剩余建议；完整边界见 [主设计记录](./issue-14-solve-with-agent.md)。

已确认：仅有卡片入口；每次新建 Agent 并直接发送；从宿主 Agent 配置选择、默认第一项；设置管理入口改为静态提示；没有预设时禁止输入及发送。用户本轮又确认了必填项与分支名校验、非 Git 项目不提供 worktree、分阶段提交及最小失败反馈。本文不新增其他异常处理。

## 目标

一个弹窗完成“编辑 prompt → 选项目 → 选已有或新建工作区 → 选 Agent 配置 → 发送”。

选择已有工作区时，也会在其中新建一个 Agent 聊天。选择新建工作区时，先创建工作区，再新建一个 Agent 聊天。任务提示词始终作为新 Agent 的第一条消息发送。

## 弹窗整体布局

- 标题：`发送到 Agent`，右上角关闭按钮。
- 标题下显示当前任务标题，只读；不在此编辑任务，也不增加完整提示词预览。
- 主体依次为多行 `prompt` 输入框、项目、一个合并的工作区下拉框、新建 worktree 时显示的 Git 分支名输入框、Agent 配置及管理提示。已有或新建工作区均不额外展示名称字段。
- Git 分支输入框在滚动区域内保留聚焦外框所需的四周留白，避免左右边框被裁切。
- 底部固定 `取消` 与 `发送` 两个按钮。桌面使用现有宿主 Modal，移动端使用宿主 sheet；主体过长时垂直滚动。
- 不再提供“已有／新建”切换按钮或工作区类型单选框；在同一个工作区下拉框中选择。

## 工作区下拉框（已确认）

```text
工作区
[ 新建普通工作区                       ▾ ]
  已有工作区 A
  已有工作区 B
  ──────────────────────────────────────
  新建普通工作区
  新建 worktree
```

- 同一个下拉框包含所选项目的已有工作区，以及“新建普通工作区”“新建 worktree”两个操作选项。
- 默认选中“新建普通工作区”。普通目录项目不提供“新建 worktree”，已有工作区和新建普通工作区仍可选。
- 不增加第二个工作区类型选择器。
- 下拉框内部的分隔线只是布局建议，不新增交互。

## 工作区名称与 Git 分支名称（已确认）

- 选择已有工作区：名称仅显示在工作区下拉框，不重复展示名称字段，不在此重命名已有工作区。
- 选择“新建普通工作区”或“新建 worktree”：名称自动使用任务标题，页面不展示名称标签或输入框。创建请求通过顶层 `title` 传入该名称。
- 选择新建 worktree 时，在工作区下拉框下面显示独立的“Git 分支名称”输入框；其他选择不显示此字段。
- Git 分支名由用户单独填写，与自动生成的工作区显示名称独立。

```text
选择已有工作区 A：
  仅在工作区下拉框显示名称，不增加名称字段。

选择新建普通工作区或新建 worktree：
  不显示工作区名称，自动使用任务标题。

仅选择新建 worktree 时增加：
  Git 分支名称 [请输入分支名称]（可编辑）
```

## prompt（已确认）

- 中英文界面均使用小写名称 `prompt`，默认预填原开场句：中文“请处理以下任务。”，英文“Please work on the following task.”。
- 这里只编辑协作指令；任务标题、描述、子步骤与来源自动附加，不提供完整模板编辑，也不把上一任务内容带入下一任务。
- 允许清空；纯空白时不添加指令内容或多余开场空行。
- 点击发送且全部输入校验通过后保存，在同一宿主内跨任务、项目及看板入口沿用；自定义文本不随语言切换改写。多窗口编辑以本次发送时的文本为最新偏好，不绑定开始编辑时的版本。
- 保存失败时停止发送，显示宿主错误 Toast 并保留输入；保存成功后，即使后续创建失败也保留。取消或关闭弹窗不保存编辑。

## 项目与预设

- 项目默认任务所属项目；手动任务可切换，GitHub 导入任务显示只读项目名。
- 未关联项目的任务先显示“请选择项目”。
- Agent 配置只显示预设名称；下拉选项沿用宿主排序，默认第一项。其 Provider、模型、thinking 及其他配置按整套预设应用，不新增参数编辑控件。
- 工作区下拉框默认选“新建普通工作区”，预设默认选列表第一项。

## 创建方式（已确认）

- 普通工作区使用项目原目录；worktree 创建独立目录和新分支。
- 用户已确认沿用 Paseo 默认 worktree 起点，即宿主解析的仓库默认分支，不增加起点选择字段。
- 点击最终发送才创建工作区；选择下拉选项不立即创建。
- Paseo 工作区显示名称本身没有 Git 分支名的约束。宿主的工作区记录将 `title` / `displayName` 与 `branch` 分开存储，创建合同也分开提供 `title` 和 `source.branchName`，工作区显示名称可以包含空格。
- 新建 worktree 时，Git 规则只约束独立的 Git 分支名，不限制工作区显示名称。已通过本地 `git check-ref-format --branch` 验证：`修复登录页样式` 合法，`修复 登录页样式` 因空格不合法。
- 用户已确认新建 worktree 时对 Git 分支名校验，不合法时在分支名输入框下提示并阻止发送；不自动修改输入。该校验只作用于 Git 分支名，不作用于工作区显示名称。

## 发送与关闭

- 最终动作名称统一为“发送”。
- 用户已确认提交顺序：校验通过后先保存 prompt，再保存必要的项目归属变更、按需创建工作区，最后新建 Agent 并发送任务提示词，打开新聊天。
- 发送按钮显示 spinner 与“发送中…”／“Sending…”，直到成功跳转或失败；保持既有表单禁用、防重复发送及关闭限制。
- 建议新 Agent 的会话标题使用任务标题。
- 用户已确认提交必填项需要齐全：项目、已有工作区选择或新建所需字段，以及 Agent 配置。新建名称自动生成，不作为用户输入项；新建 worktree 需填写有效 Git 分支名。未填或不合法时就地提示并阻止发送。
- “取消”或关闭弹窗不执行发送，不创建工作区，也不保存 prompt 或项目归属变更。
- 没有预设时，表单输入与发送不可用，保留管理预设提示及关闭入口；这是需求提出者已明确确认的处理。

用户已确认：任一步返回失败就停止本次流程，显示宿主错误 Toast 并保留弹窗输入；此前已成功的操作不自动回滚，不自动重试。没有因此授权其他恢复或额外异常处理。
