## 状态与范围

已确认：仅有卡片入口；每次新建 Agent 并直接发送；从宿主 Agent 预设选择、默认第一项；设置管理入口改为静态提示；没有预设时禁止输入及发送。用户本轮又确认了必填项与分支名校验、非 Git 项目不提供 worktree、分阶段提交及最小失败反馈。本文不新增其他异常处理。

## 目标

一个弹窗完成“选项目 → 选已有或新建工作区 → 选 Agent 预设 → 发送”。

选择已有工作区时，也会在其中新建一个 Agent 聊天。选择新建工作区时，先创建工作区，再新建一个 Agent 聊天。任务提示词始终作为新 Agent 的第一条消息发送。

## 弹窗整体布局

- 标题：`发送到 Agent`，右上角关闭按钮。
- 标题下显示当前任务标题，只读；不在此编辑任务，也不增加完整提示词预览。
- 主体依次为项目、一个合并的工作区下拉框、新建 worktree 时显示的 Git 分支名输入框、Agent 预设及管理提示。新建时不展示工作区名称；选择已有工作区时沿用之前的只读名称展示。
- 底部固定 `取消` 与 `发送` 两个按钮。桌面使用现有宿主 Modal，移动端使用宿主 sheet；主体过长时垂直滚动。
- 不再提供“已有／新建”切换按钮或工作区类型单选框；在同一个工作区下拉框中选择。

## 工作区下拉框（已确认）

```text
工作区
[ 新建普通工作区                       ▾ ]
  已有工作区 A
  已有工作区 B
  ──────────────────────────────────────
  新建普通工作区
  新建 worktree
```

- 同一个下拉框包含所选项目的已有工作区，以及“新建普通工作区”“新建 worktree”两个操作选项。
- 默认选中“新建普通工作区”。普通目录项目不提供“新建 worktree”，已有工作区和新建普通工作区仍可选。
- 不增加第二个工作区类型选择器。
- 下拉框内部的分隔线只是布局建议，不新增交互。

## 工作区名称与 Git 分支名称（已确认）

- 选择已有工作区：输入框显示所选工作区名称，置灰且不可编辑，不在此重命名已有工作区。
- 选择“新建普通工作区”或“新建 worktree”：名称自动使用任务标题，页面不展示名称标签或输入框。创建请求通过顶层 `title` 传入该名称。
- 选择新建 worktree 时，在工作区下拉框下面显示独立的“Git 分支名称”输入框；其他选择不显示此字段。
- Git 分支名由用户单独填写，与自动生成的工作区显示名称独立。

```text
选择已有工作区 A：
  工作区名称 [已有工作区 A]    （置灰）

选择新建普通工作区或新建 worktree：
  不显示工作区名称，自动使用任务标题。

仅选择新建 worktree 时增加：
  Git 分支名称 [请输入分支名称]（可编辑）
```

## 项目与预设

- 项目默认任务所属项目；手动任务可切换，GitHub 导入任务显示只读项目名。
- 未关联项目的任务先显示“请选择项目”。
- Agent 预设只显示预设名称；下拉选项沿用宿主排序，默认第一项。其 Provider、模型、thinking 及其他配置按整套预设应用，不新增参数编辑控件。
- 工作区下拉框默认选“新建普通工作区”，预设默认选列表第一项。

## 创建方式（已确认）

- 普通工作区使用项目原目录；worktree 创建独立目录和新分支。
- 用户已确认沿用 Paseo 默认 worktree 起点，即宿主解析的仓库默认分支，不增加起点选择字段。
- 点击最终发送才创建工作区；选择下拉选项不立即创建。
- Paseo 工作区显示名称本身没有 Git 分支名的约束。宿主的工作区记录将 `title` / `displayName` 与 `branch` 分开存储，创建合同也分开提供 `title` 和 `source.branchName`，工作区显示名称可以包含空格。
- 新建 worktree 时，Git 规则只约束独立的 Git 分支名，不限制工作区显示名称。已通过本地 `git check-ref-format --branch` 验证：`修复登录页样式` 合法，`修复 登录页样式` 因空格不合法。
- 用户已确认新建 worktree 时对 Git 分支名校验，不合法时在分支名输入框下提示并阻止发送；不自动修改输入。该校验只作用于 Git 分支名，不作用于工作区显示名称。

## 发送与关闭

- 最终动作名称统一为“发送”。
- 用户已确认提交顺序：有项目归属变更时先保存，再按需创建工作区，最后新建 Agent 并发送固定模板任务提示词，打开新聊天。
- 建议新 Agent 的会话标题使用任务标题。
- 用户已确认提交必填项需要齐全：项目、已有工作区选择或新建所需字段，以及 Agent 预设。新建名称自动生成，不作为用户输入项；新建 worktree 需填写有效 Git 分支名。未填或不合法时就地提示并阻止发送。
- “取消”或关闭弹窗不执行发送，不创建工作区，也不保存项目归属变更。
- 没有预设时，表单输入与发送不可用，保留管理预设提示及关闭入口；这是需求提出者已明确确认的处理。

用户已确认：任一步返回失败就停止本次流程，显示宿主错误 Toast 并保留弹窗输入；此前已成功的操作不自动回滚，不自动重试。没有因此授权其他恢复或额外异常处理。
